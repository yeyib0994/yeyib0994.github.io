# pi-web：把 pi 编程智能体搬进浏览器

如果你已经在使用 [pi 编程智能体](https://github.com/badlogic/pi-mono)，大概率遇到过这样的尴尬：想回头翻一条上周的对话，却得在终端历史里 grep 会话路径；想换一个方向试试，又怕把正在进行的对话搞乱。

**pi-web** 就是为了解决这些"小摩擦"而生的——它是一个本地网页界面，读取你机器上已有的 pi 会话文件，在浏览器里提供会话管理、实时对话、模型配置、技能管理与项目文件预览。它的核心理念很简单：你的数据留在本地，体验却可以像 SaaS 一样顺滑。

## 为什么需要它

pi 本身是个命令行的编程智能体，能力很强，但"回顾"和"探索"这两件事在 CLI 里并不轻松。pi-web 把这两件事接了回来：

- **把历史工作接回来**：打开网页就能按项目找到以前的 pi 对话，不必在终端里翻文件或记住会话路径。
- **放心试不同方向**：可以从某条历史消息重新开始，也可以复制出一条独立的新路线，探索方案时不怕弄乱原来的对话。
- **跨分支工作**：在侧边栏切换 Git worktree，让新会话和文件浏览跟随你选择的 checkout。
- **边聊边看项目文件**：左侧浏览项目文件，右侧打开源码、文档、图片、音频和 PDF；文件变化会自动刷新。
- **随时掌握会话状态**：在顶部就能看到上下文占用、花费、压缩结果和系统提示，长会话不再像黑箱。
- **少离开当前界面**：模型、登录 / API key、模型测试和技能开关都能在网页里处理。

## 三分钟跑起来

最轻量的方式是不安装、直接运行：

```bash
npx @agegr/pi-web@latest
```

或者全局安装后用命令启动：

```bash
npm install -g @agegr/pi-web
pi-web
```

服务就绪后默认打开 [http://localhost:30141](http://localhost:30141)，命令行还会尝试帮你自动打开浏览器。

想自定义也很简单：

```bash
pi-web --port 8080              # 自定义端口
pi-web --hostname 127.0.0.1     # 仅本机访问
pi-web -p 8080 -H 127.0.0.1     # 组合使用
pi-web --no-open                # 不自动打开浏览器

PORT=8080 pi-web                # 也支持环境变量
PI_WEB_NO_OPEN=1 pi-web         # 适用于后台服务或开机自启
```

## 两个容易混淆的概念：Fork vs 会话内分支

这是 pi-web 里最值得讲清楚的一点，因为它们解决的是不同的"试错"需求：

> **Fork**：创建一条全新的 `.jsonl` 文件，是一条真正独立的会话路线。适合"我想从这一步另起炉灶，原对话原封不动"的场景。
>
> **Edit from here（会话内分支）**：在同一个 `.jsonl` 文件内部切出一个分支，多个分支共享同一个父节点。适合"在同一段对话里尝试几个不同走向"的场景。

简单说：**Fork 是物理分家，会话内分支是逻辑分叉**。理解了这一点，你就能放心地各种试，再也不怕把对话玩坏。

## 数据都放在哪

pi-web 不碰你的代码，只读不写你的会话内容，它关心的目录很明确：

- **默认数据目录**：`~/.pi/agent/sessions`。可以通过环境变量 `PI_CODING_AGENT_DIR` 指向另一个 pi agent 目录。
- **会话文件格式**：`~/.pi/agent/sessions/<编码后的工作目录>/<时间戳>_<uuid>.jsonl`。
- **模型配置**：Models 面板读写 pi agent 目录下的 `models.json`，列表和默认值来自 pi 自身配置。
- **文件访问边界**：浏览和预览只面向当前选择的项目目录，以及会话中出现过的工作目录——这是一道安全边界，避免误读系统文件。

如果你用到 Git worktree，什么时候会出现分支切换器、新建目录落在哪里、删除会牵连什么，可以看 [pi-web 里的 Worktree](./docs/worktrees.zh-CN.md)。

## 给想改代码的同学

项目本身是个 Next.js 应用，技术栈是 `next + react + typescript + tailwindcss`，数据流走的是自研 SSE + fetch 状态机。本地开发：

```bash
npm install
npm run dev
```

常用检查：

```bash
node_modules/.bin/tsc --noEmit
npm run lint
```

一个**重要提醒**：开发时千万别跑 `next build` / `npm run build`。它会往 `.next/` 写东西，容易把正在跑的 dev server 搞乱。构建留给发布流程。

整体结构可以分成三块：`app/api/*` 是能力出口（驱动 AgentSession、鉴权、文件、模型、技能等），`components/*` 是界面骨架，`lib/*` + `hooks/*` 负责把本地会话文件解析、规范化并驱动流式交互。

## 小结

pi-web 不是要取代 pi 的命令行，而是给它配一个"驾驶舱"：当你需要回顾、对比、试错、看文件时，浏览器比终端更顺手。它本地优先、零数据上传，几分钟就能上手。

如果你也经常在终端里翻会话、也想更安全地探索不同方案，不妨 `npx @agegr/pi-web@latest` 跑一下，看看同一个 pi 会话在网页里长什么样。
