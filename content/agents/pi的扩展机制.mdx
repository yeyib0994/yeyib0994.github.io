## 一、核心认知：什么是 Pi Agent Extensions？

### 1\.1 扩展本质

Pi Agent Extensions 是**基于 TypeScript 的动态代码模块**，是 Pi 生态中最高自由度的定制方式。它可以深度介入 Agent 运行全生命周期，区别于静态 Markdown 编写的 Skills 技能，Extensions 支持动态逻辑、状态持久化、事件响应，是真正意义上的「Agent 插件系统」。

### 1\.2 核心能力矩阵

Extensions 覆盖 Pi Agent 几乎全部定制场景，核心能力如下：

- **生命周期事件监听**：监听会话启动、上下文压缩、项目加载、指令执行等 25\+ 官方事件钩子

- **自定义工具注册**：为 LLM 注册专属可调用工具，拓展 Agent 操作边界

- **自定义命令/快捷键**：注册全局斜杠命令、自定义键盘快捷键

- **UI 界面定制**：自定义底部状态栏、编辑器悬浮面板、顶部导航、弹窗组件

- **权限与安全管控**：配置路径保护、危险操作二次确认、项目信任策略

- **动态能力切换**：根据运行时状态动态启停 Agent 工具、切换工作模式

- **上下文优化**：自定义会话上下文压缩、内容摘要策略，优化 Token 消耗

### 1\.3 Extensions vs Skills 核心区别

|特性|Extensions（扩展）|Skills（技能）|
|---|---|---|
|编写语言|TypeScript（动态代码）|Markdown（静态文本）|
|运行能力|支持运行时逻辑、事件响应、状态存储|仅静态 Prompt 注入，无动态逻辑|
|定制深度|底层内核级定制（UI/事件/权限/工具）|业务层能力补充（编码规则、场景提示）|
|适用场景|插件开发、功能拓展、底层定制|场景化编码规范、通用技能提示|

## 二、扩展目录与安装规范

### 2\.1 目录优先级

Pi Agent 会从两个固定目录加载扩展，**项目局部扩展优先级高于全局扩展**：

- **项目局部目录**：`./.pi/extensions/`（仅当前项目生效）

- **全局目录**：`~/.pi/agent/extensions/`（所有项目全局生效）

所有后缀为 `.ts` 的文件会被自动识别为扩展模块，无需额外配置。

### 2\.2 扩展安装方式

Pi 提供极简的扩展安装指令，支持 NPM、Git 源安装第三方扩展：

```Plain Text
# 从 NPM 安装扩展
pi install npm:扩展包名

# 从 Git 仓库安装扩展
pi install git:仓库地址

# 重载所有扩展（修改/安装后必执行）
/reload
```

## 三、核心 API 与生命周期事件

所有扩展默认接收 `ExtensionAPI` 实例，通过该实例实现事件监听、工具注册、状态操作等核心能力。

### 3\.1 基础扩展模板

最简扩展结构仅需默认导出一个执行函数，框架会自动注入 API 实例：

```Plain Text
// ~/.pi/agent/extensions/demo-extension.ts
export default function (api: ExtensionAPI) {
  // 扩展初始化逻辑
  api.log("Demo 扩展加载成功！");

  // 监听会话启动事件
  api.on("session_start", () => {
    api.agent.say("✅ 智能体会话已启动，自定义扩展已就绪");
  });
}
```

### 3\.2 高频核心事件

Pi 官方提供 20\+ 生命周期事件，以下是开发中最常用的核心事件：

- `session_start`：新会话启动时触发，用于初始化配置、状态重置

- `session_before_compact`：会话上下文压缩前触发，可自定义压缩策略

- `project_trust`：项目信任状态变更触发，用于权限管控

- `command_before_run`：自定义命令执行前触发，可做参数校验、拦截

- `extension_reload`：扩展重载时触发，用于资源释放、状态更新

## 四、完整实战：开发一款状态监控扩展

我们实战开发一款**会话状态监控扩展**，实现：会话启动提示、重载通知、上下文压缩监听、运行状态日志打印，覆盖 80% 基础扩展开发场景。

### 4\.1 完整代码实现

创建文件 `~/.pi/agent/extensions/status-monitor.ts`：

```Plain Text
import type { ExtensionAPI, Agent } from "@mariozechner/pi-coding-agent";

// 扩展默认导出
export default function StatusMonitorExtension(api: ExtensionAPI) {
  // 扩展初始化日志
  api.log("🚀 状态监控扩展初始化完成");

  // 1. 监听会话启动
  api.on("session_start", () => {
    api.log("✅ 新 AI 会话已启动");
    api.agent.say("🤖 状态监控已开启，实时追踪会话运行状态");
  });

  // 2. 监听上下文压缩事件
  api.on("session_before_compact", (ctx) => {
    api.log(`📦 即将压缩会话上下文，当前消息数：${ctx.messageCount}`);
  });

  // 3. 监听扩展重载事件
  api.on("extension_reload", () => {
    api.log("🔄 扩展已重载，状态已更新");
  });

  // 4. 注册自定义状态查询命令 /status
  api.registerCommand({
    name: "status",
    description: "查询当前 Agent 运行状态",
    async run(agent: Agent) {
      agent.say(`
      📊 当前 Agent 运行状态：
      ✅ 扩展正常运行
      🕒 会话时间：${new Date().toLocaleString()}
      🛠️  动态工具已启用
      `);
    },
  });
}

// 可选：扩展销毁逻辑
export async function deactivate(agent: Agent) {
  agent.say("❌ 状态监控扩展已卸载");
}
```

## 五、高级开发技巧

## 六、常见问题排查

- **扩展不生效**：检查文件路径是否正确、后缀是否为 `.ts`，执行 `/reload` 重载

- **类型报错**：更新 pi\-coding\-agent 依赖，匹配最新类型定义

- **命令无法触发**：检查命令名是否唯一，避免与内置命令冲突

- **事件不触发**：确认事件名称拼写，部分事件仅特定场景触发（如上下文压缩）
